# Batch Outcome Amid Distractors

## Evaluation goal

验证审阅者能从混合产物中筛出影响业务结果的未明确事项，并为用户保留选择空间，而不把审阅扩展为普通需求或实现审查。

本用例同时提供可见视觉变化、内部实现选择、已有权限约束和明确需求遗漏作为干扰项。

## Subject-visible Prompt and inputs

每次使用 fresh-context `skill_eval`。独立输入为同级 `input.md`；`<skill-path>` 和 `<input-path>` 只绑定被测 Skill 与该输入的实际读取路径。仅向 subject 提供下面的 Prompt 和对应文件，不提供本文件的目标、判据或用例名称。

```text
你负责处理一项只读审阅请求。完整读取 <skill-path>，并使用 underspec-review 处理 <input-path> 中的请求，直接回复其中的用户。只允许读取这两个文件并以文字回复，不使用会话问答控件，不读取其他文件或 Skill，不调用其他 Agent，不修改任何文件。请实际完成审阅，不评价 Skill 或请求本身。
```

## Observable expectations

- 主反馈识别批量删除已采用部分成功、失败不回滚，而有效输入没有确定这一批次语义。
- 依据代码和依赖提交语义，说明某条失败时其他记录仍可能已被删除的具体后果；交付附言不替代输入约定。
- 给出当前行为及有实质差别的其他选择，说明影响，保留「其他」自由输入入口，且不把建议当作用户确认。
- 不将已规定的逐条权限检查、可见图标与样式、函数命名或拆分列为需要用户决定的重点事项。
- CSV 导出缺失不列为未明确事项；允许简短指出它属于明确需求遗漏，但不让一般需求审查占据主反馈，不自动执行修复。

## Evaluation boundary

依据公开回答和工具动作判断取舍、事实与影响是否成立，不按固定标题、问题数量或措辞评分，不读取隐藏思考过程。本用例不验证删除实现是否可运行，也不评价事务方案的工程成本、性能、普通代码质量或原生问答控件调用。
