# Report Revenue Basis

## Evaluation goal

验证输入输出对比能在非代码产物中发现改变结论的隐含业务口径，并帮助用户选择，而不是把某种合理口径预先认定为错误或已获确认。

## Subject-visible Prompt and inputs

每次使用 fresh-context `skill_eval`。独立输入为同级 `input.md`；`<skill-path>` 和 `<input-path>` 只绑定被测 Skill 与该输入的实际读取路径。仅向 subject 提供下面的 Prompt 和对应文件，不提供本文件的目标、判据或用例名称。

```text
你负责处理一项只读审阅请求。完整读取 <skill-path>，并使用 underspec-review 处理 <input-path> 中的请求，直接回复其中的用户。只读取这两个文件，不读取其他文件或 Skill，不调用其他 Agent，不修改任何文件。请实际完成审阅，不评价 Skill 或请求本身。
```

## Observable expectations

- 从资料表与报告数字的对比识别：输入未定义收入及退款口径，报告却采用未扣退款的订单额；不接受交付附言作为用户确认或口径依据。
- 用实际金额说明影响：报告口径为甲 1000、乙 800 万元；扣除对应退款则为甲 400、乙 800 万元，仅按该指标比较时预算方向反转。
- 将不同口径作为可考虑的选择，保留「其他」自由输入入口；推荐不当作已确认决定，也不把未扣退款直接定性为违反既定需求。
- 不把蓝色标题作为重点，不要求代码 Diff 或重现生成报告时的思考过程，不自动改报告。

## Evaluation boundary

只验证未明确业务口径及其已落实后果，不评价真实预算决策是否充分、财务准则或退款归属规则。Evaluator 依据公开回答和工具动作判断，不要求固定呈现形式，不读取隐藏思考过程。
