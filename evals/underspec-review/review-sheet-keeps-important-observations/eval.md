# Review Sheet Keeps Important Observations

## Evaluation goal

验证阅读时间受限时，审阅者仍保留分析中发现的重要业务观察，并将真正待决定的选择交付为可直接作答的答卷。

本用例根据退款分析的真实实践反馈设计固定的任务与代码摘录，验证日期联动、未归类差额表达、明确失败与日期义务、未决空值契约的处理，不复刻实际业务仓库的全部实现。

## Subject-visible Prompt and inputs

每次使用 fresh-context `skill_eval`。独立输入为同级 `input.md`；`<skill-path>` 和 `<input-path>` 只绑定被测 Skill 与该输入的实际读取路径。仅向 subject 提供下面的 Prompt 和对应文件，不提供本文件的目标、判据或用例名称。

```text
完整读取 <skill-path>，并使用 underspec-review 处理 <input-path> 中的请求，直接回复其中的用户。只允许读取这两个文件并以文字回复，不使用会话问答控件，不读取其他文件或 Skill，不调用其他 Agent，不修改文件。请实际完成审阅，不评价 Skill 或任务本身。
```

## Observable expectations

- 用户无需整理报告，就能分别回答跨页面日期继承与回写、未归类差额表达的选择；每题的当前行为、影响、其他方向和自由填写入口明确，具备清楚的作答位置或回复方式。
- 两项选择都保留在本次答卷中，不因两分钟阅读限制、交付附言或其他高优先级观察而省略。保留已确认的全店统计口径，不把分母重新变成选择题。
- 在辅助说明中保留事件请求失败后展示旧数据、日期请求失败后保留旧值、首次进入绕过日期限制的事实、依据与影响；允许合并相关问题，但不能只报数量或让用户选择是否实现既定要求。
- 空值类型与接口说明的冲突作为无法判断事项，说明正式契约与真实空值响应缺失，不认定已发生空值故障，不转成产品选择题。
- 接受调用方已认可的 Spec；不因原始问答缺失而重新要求确认全部需求。未改文件、未扩大为完整 Task Review，新增观察有输入输出依据。

## Evaluation boundary

按用户能否直接作答、重要观察是否保留及其归属判断，不按固定标题、题数或字段原句评分。空态和并发议题不作为本例的唯一定性断言；涉及这些议题时仍需区分有效输入、已观察行为及推断。

本例验证隔离环境中的文字版答卷，不验证原生问答控件调用，不执行业务代码或验收真实接口。Evaluator 只依据公开回答和工具动作判断，不读取隐藏思考过程。
