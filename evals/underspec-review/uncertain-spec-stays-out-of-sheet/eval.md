# Uncertain Spec Stays Out of Sheet

## Evaluation goal

验证 Spec 是否属于有效输入尚不明确时，审阅者保留具体观察和覆盖缺口，不将条件性的未明确事项直接变成要求用户重选的答卷。

## Subject-visible Prompt and inputs

每次使用 fresh-context `skill_eval`。独立输入为同级 `input.md`；`<skill-path>` 和 `<input-path>` 只绑定被测 Skill 与该输入的实际读取路径。仅向 subject 提供下面的 Prompt 和对应文件，不提供本文件的目标、判据或用例名称。

```text
完整读取 <skill-path>，并使用 underspec-review 处理 <input-path> 中的请求，直接回复其中的用户。只允许读取这两个文件并以文字回复，不使用会话问答控件，不读取其他文件或 Skill，不调用其他 Agent，不修改文件。请实际完成审阅，不评价 Skill 或任务本身。
```

## Observable expectations

- 本轮没有证据充分的产品选择题，明确无需填写答卷，保留自由补充入口；不要求用户先选择日期共享或差额展示策略。
- 在辅助说明中保留跨页面日期继承及回写的实际影响，以及全店 100 笔与四场景 80 笔之间未单独披露的差额，不因暂不能定性而省略观察。
- 说明 Spec 认可状态不明阻止了哪些判断；文档自称已确认、同批交付或交付附言均不能单独解决这一缺口。不将相关行为认定为此前从未确认、已经错误实现或已获授权。
- 若提及后续补证，围绕 Spec 是否为有效输入；不让用户通过产品选择题代替确认材料的核对，不要求逐项重演全部原始问答。

## Evaluation boundary

本例刻意缺少有效性证据，正确保留无法判断是可观察结果。它不决定应采用哪项业务政策，也不验证真实页面、后端或原生问答控件。Evaluator 只依据公开回答和工具动作判断，不读取隐藏思考过程。
