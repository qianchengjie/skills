# 测试分析与质量审查

围绕给定任务，独立判断应该保护哪些关键行为，以及现有测试的保护能力与保留价值，为 human 或调用方提供有依据、可核对的审查结果。

本 Skill 只提供审查判断，不修改被审代码或决定任务推进。具体实现、用例设计和返修由既有执行角色负责。

## 依据与时点

依据任务目标、范围、验收要求及已确认契约，结合必要代码、调用关系和测试取证。既有实现说明现状，保护义务须由任务及相关契约支持；保留适用条件与上下游责任。

能够查明的技术事实先查证；仍缺业务决定时，说明具体问题及影响范围，交上游确认。满足已确认契约的工程设计由实现者自主决定。

- **实现前**：独立分析关键行为与测试边界，说明预期依据、关注理由和未决事项，交给 human 审查。
- **实现后**：结合实际实现和测试完成下述五方面审查。以 human 已审边界为重点，仍可提出有依据的新发现。

## 审查方法

| 方面 | 如何形成判断 |
| --- | --- |
| 保护目标的价值 | 从任务新增、改变或必须保持的承诺出发，识别会改变结果或关键约束的条件及其组合。用违反契约的具体错误与实际影响说明关注理由，形成有来源的关键边界清单。 |
| 关键边界的覆盖 | 核对目标行为发生时，测试是否实际形成所需条件，相关结果或约束是否进入断言。结合不同层级的相关测试集合及其连接判断已有保护与缺口，认可已有测试的有效承接。 |
| 测试判定的可信度 | 从独立于被测实现的契约、已确认实例或可信关系推导预期。核对 fixture 的业务事实是否一致，Mock 是否符合依赖契约并保留目标行为到断言之间必要的效果。 |
| 缺陷检测能力 | 选取会破坏关键承诺的具体错误，指出预计失败的断言；重要保护或精简判断优先取得少量定向变异的实测证据。结合等价性、契约范围和其他已有保护判断未检出的错误是否形成重要缺口，额外必要性尚未成立的补测作为增强候选。 |
| 保留价值与维护负担 | 考察移除用例、断言或夹具会失去什么额外保护，以及仍满足目标契约的改动是否会使它失败。若同一断言兼有有效保护与非必要约束，优先收窄后者而非整体删除，并说明重要保护如何承接；依据具体耦合或维护记录判断负担。 |

实测使用隔离副本或项目已有工具的隔离机制，保持被审版本不变。先确认原始测试通过，再逐个施加目标错误并运行对应测试，确认失败来自目标契约被破坏；无效变异、构建或环境失败不计为检出。精简判断需比较删减前后测试集合对同一错误的检出情况。

## 返回可复核的结果

由其他审查入口调用时，沿用其范围与输出约定，将本轮判断和分项数据纳入对应审查结论。

逐项给出判断、依据位置和实际影响，区分确定问题、增强或精简候选，以及尚不能确认的事项。文案、样式、简单映射和无状态计算同样依据保护价值判断。

按阶段与实际检查对象提供分项数据，使每个计数都能对应具体清单：

- 关键行为与边界清单及数量；实现后分别汇总已有保护、确定缺口和未验证项。
- 实现后先查明项目已有覆盖率能力，优先复用与被审版本相符的报告；无适用报告且执行条件允许时，使用已有能力收集本任务相关范围的覆盖率。报告行、分支覆盖率、来源和测试范围；未获取有效数据时，说明未检查的具体原因及其对结论的影响。
- 实际核对的测试或断言，以及预期、fixture、Mock 的问题与未决数量。
- 目标错误的实测内容、测试范围、结果及检出数／有效已验证目标数；静态推演单列理由，未执行时说明原因及对保护或精简结论的限制。
- 精简候选及其保护变化；有记录时附运行、波动或维护数据及观测范围。

明确统计范围、边界分组和分母；清单覆盖数不证明清单完整或测试充分，各方面不合成总分。代码覆盖率用于定位检查线索；已有明确覆盖率验收要求时据此检查，未规定时，补测义务依据具体行为与保护缺口，不自行设置通过门槛。区分静态推演与实际验证，证据不足记为未知，保留其他有依据的结论；仅有静态证据时不声称已测得运行或维护成本。
