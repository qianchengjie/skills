# 重新找方向

## 核心原则

真正目标不等于当前方案成功。调用后先暂停当前路线，在判断是否继续前，必须尝试一条结构上不同的方向。

重新找路不等于强行换路。替代方向经比较后更差，或当前只是普通执行障碍时，`keep` 是正确结论。

## 流程

按顺序完成：

1. **Goal：** 恢复用户真正想达到的结果，把它与“让当前方案成功”分开。
2. **Current Direction：** 简要描述当前路线，只建立参照，不在这里优化它。
3. **Why Stuck：** 说明为什么现在值得重新找路，例如没有进展、成本持续增加、新补丁不断出现、关键未知未解决，或路线偏离目标。不预设原因一定是复杂度。
4. **Break Current Path：** 明确回答：`如果暂时禁止继续沿当前这条路，还能怎么达到真正目标？`
5. **Search Other Directions：** 先提出至少一个结构上真正不同的方向，再做决定。可按当前问题重新定义目标、改变实现路径、约束、边界或责任主体，使用已有机制，先验证关键未知，或暂时不解决当前问题；这些是候选来源，不是 checklist。
6. **Decide：** 只选择一个 verdict。
7. **Smallest Next Move：** 只给一个成本低、信息增益高、能尽快证伪判断的下一步；不在本次调用中展开整套新方案。

## 判断标准

| Verdict | 使用条件 |
| --- | --- |
| `keep` | 方向有证据支持，当前只是普通执行障碍 |
| `adjust` | 目标不变，但应换一条结构上不同的路线 |
| `abandon` | 当前方向本身不值得继续 |
| `investigate` | 关键事实不足，方向判断需要先取得证据 |

`优化 A`、`简化 A`、`分阶段实施 A` 仍是同一路线。不同方向必须改变问题框架、实现路径、约束、边界、责任主体或首先解决的未知之一。

## 输出

保持轻量，根据上下文自然组织，不强制固定字段或固定结构。

- 不直接暴露 `Verdict`、`Goal`、`Current Direction` 等内部字段。
- 根据当前判断，只讲对用户有帮助的信息，通常包括：
  - 当前方向是否值得继续；
  - 需要换路或比较路线时，说明结构上真正不同的方向；
  - 下一步最值得先做什么。
- 需要标题时使用自然、易懂的中文标题。
- 用户继续询问“还有其他方向吗”时，提供尚未讨论过、结构上不同的候选，不重复同一路线的轻量变体。
- 不要为了使用 skill 而制造变化。

## 示例

两个 onboarding 方案分别牺牲激活率和风控效果时，不要直接选 A、选 B 或折中。可将方向调整为“先让用户完成低风险核心动作，只在高风险能力首次使用时升级核验”；最小下一步是找出造成主要滥用的一个能力，验证按需核验是否同时改善有效激活与滥用率。

## 常见错误

| 错误 | 修正 |
| --- | --- |
| 立刻继续优化当前方案 | 先完成 `Break Current Path` |
| 给出多个同一路线的轻量变体 | 至少改变一个结构维度 |
| 为了显得有用而强制换方向 | 普通执行障碍选择 `keep` |
| 一次展开完整替代方案 | 收敛为一个可证伪的最小下一步 |
