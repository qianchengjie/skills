# 下一步做什么

## 定位

whats-next 是开发工作流中的导航 skill，帮助用户根据当前意图了解下一步有哪些可用选择，以及这些选择分别适用于什么情况。

## 导航方式

根据用户当前意图和已有会话上下文，识别相关入口。适用入口明确时，直接推荐并简述理由；存在多个合理选择时，说明少量相关选择各自适用的情况，帮助用户选择。用户希望了解整体流程时，展示相关的常见 flow。

默认依据已有上下文提供导航。需要确认某个 skill 的职责时，按需查阅其当前说明；具体材料的评审和执行准备检查由对应 skill 承担。

## 入口地图

入口地图覆盖组合 workflow 中主要的工作入口；辅助 skill 仅在其用途本身构成常见导航需求时纳入。

| 用户当前想做什么 | 可用入口 | 适用情况 |
| --- | --- | --- |
| 澄清需求或方案 | `grill-with-docs` | 通过当前讨论梳理未决问题，并记录领域语言和决定 |
| 推进跨会话的复杂探索 | `wayfinder` | 工作超出单个会话，需要将未决问题组织成决定票据并逐项解决 |
| 将讨论整理成 Spec | `to-spec` | 将已有讨论和决定整理为需求说明 |
| 拆分并生成开发票 | `to-tickets` | 需要将 Spec、计划或已有讨论拆成分批交付的开发票，并明确前置依赖 |
| 判断或落实需求拆分 | `task-steward` | 需要判断已有需求是否需要拆分，或复核已有拆分的粒度、前置依赖与需求覆盖 |
| 开始实现已明确的开发任务 | `execute-task` | Spec 或其他材料已明确单个任务的目标、范围与验收，需要组织实现、审查和返修 |
| 管理项目知识库 | `knowledge-steward` | 需要维护已有知识的内容与引用关系，或判断 Spec、任务、研究、原型等材料的保留与清理 |
| 读取或管理架构决定 | `architecture-steward` | 需要读取、创建、修改或确认项目的长期架构约定 |
| 维护项目规则 | `rule-steward` | 需要建立、查询或维护项目规则 |

## 常见 flow

- **从需求到开发**：需要澄清需求时，用 `grill-with-docs`；探索需要跨会话推进时，用 `wayfinder`。讨论需要形成 Spec 时，用 `to-spec`；需要生成分批交付的开发票时，用 `to-tickets`。
- **从需求到执行**：需要判断或落实需求拆分时，用 `task-steward`；无需拆分时保留原需求，需要时形成多个平级 task。目标、范围与验收已明确时，可以直接用 `execute-task`。这套组合在实现阶段采用 Superpowers 的 `test-driven-development` 作为方法，由任务交接时指定。
- **知识库维护**：开发、探索或日常维护中，需要处理知识更新、查找与引用问题或材料去留时，可选择 `knowledge-steward`。任务或需求完成后也可以按需进入这一环节；现有材料满足需要时，继续已有后续工作或结束本轮。
- **维护项目约定**：需要处理长期架构决定或项目规则时，分别使用 `architecture-steward` 或 `rule-steward`。约定维护完成后，根据当时的意图和已有上下文选择后续入口。

## 职责边界

本 skill 提供导航建议，不修改项目 artifact，也不自动调用推荐的 skill。具体工作由用户或调用方安排，并遵循对应 skill 的执行约定。
