# 项目知识库管理

在授权范围内管理项目知识及其承载材料，使有效内容准确、可找到、可追溯。已有文档、Spec、任务、研究笔记、原型记录及其引用都可以承载项目知识；根据实际需要维护内容、组织关系和材料去留。

## 确定本轮管理问题

根据用户意图确定本轮主题、涉及材料、使用需要和操作范围。沿项目约定、目录和引用读取相关资料，识别已确认变化、内容过时或冲突、查找与引用问题，以及材料的实际依赖。涉及开发工作流 skills 的产物时，按需读取 [工作流材料职责](references/workflow-materials.md)。

以具体管理问题决定本轮动作和完成范围。知识库的长期组织方式尚未确定时，先沿用现有材料；只有当前问题确实依赖新的组织决定时，才将该决定交给调用方。现有内容准确、引用可用且满足使用需要时，维持现状即可。

## 判断内容与依据

区分已确认约定、观察或验证结果、候选方案和未决问题。以已确认需求和决定判断有效约定，以交付、验收、研究和排障证据判断已实现或已验证的范围；必要时定向读取代码、测试或契约。结论保留环境、时间、前提与限制，摘要、索引和任务状态用于定位具体依据。

涉及功能交付时，整体结论沿用已有整体验收依据或用户对实际已交付结果的明确确认；子任务证据按其覆盖范围使用。研究、排障和原型结论可以按已有证据独立保留，其验证结果与生产方案的采纳分别判断。

材料冲突时，查找明确的替代或裁决依据。仍无法确定的内容保留为具体未决项，继续处理不受影响的部分。新的需求取舍交给调用方，内容维护承接已经作出的决定。

## 按问题选择维护动作

| 实际需要 | 维护动作 |
| --- | --- |
| 已确认变化尚未反映，或现有内容有可核对的错误 | 在授权内更新相关材料的受影响部分，保留有效内容、适用条件与依据。 |
| 内容重复、入口难找、引用失效或相互矛盾 | 按材料职责厘清当前依据、摘要入口和历史证据的关系，修正引用；有裁决依据时协调相关表述。 |
| 已有明确的知识使用问题，现有材料尚不能回答 | 找到该问题的提出者、用途与依据，沿现有材料及引用核对实际缺口，再决定需要补充的内容。 |
| 材料是否继续保留或纳入 Git 存在疑问 | 按内容价值、实际依赖和访问需要给出处理结论，并在相应授权内落实。 |

普通材料的内容和引用更正按已有维护授权直接处理。对项目规定须由专门入口维护的内容，需要改动时将目标、具体变化和依据交给对应入口，按其协议写入和确认。领域、架构、规则和任务的专门维护职责见工作流材料职责；已有有效内容可以直接读取和引用。

补充内容的依据是已经明确的使用问题及其实际影响。现有材料及其引用能回答该问题时继续沿用；确有缺口时优先补充相关材料，需要新增载体时再按项目约定或本轮安排处理。承载方式确需另作决定时，返回具体选择及其影响，继续完成不依赖该决定的维护。

按材料职责组织内容：当前说明表达当前有效语义，历史决定和实验记录保留原始事实，通过更正说明或替代引用关联后续变化。区分业务要求、外部契约与本项目的实现选择、配置和技术限制，使后续使用者能判断适用范围。

## 处理材料去留

涉及保留或清理问题时，逐份或按相同理由分组判断：

- **继续保留**：仍承载独有的有效内容、未决问题所需证据，或仍被后续任务、验收和外部链接依赖。
- **可以退出活跃材料**：有效内容已有可靠承接，在用引用已处理，且需要追溯的来源仍可访问。说明判断依据及尚需完成的动作。

概述不能替代下游依赖的具体字段、协议、实验记录或验收条件。无法确认内容已完整承接或引用已迁移时，保留原材料并说明缺口。已有且可访问的 Git 或任务系统历史可作为追溯来源；是否另行归档取决于项目约定和实际访问需要。

需要 Git 处理建议时，结合项目约定、当前跟踪与修改状态、协作访问及追溯需要，说明首次纳入、提交已有修改、维持现状或无需纳入的理由。

迁移、归档、删除和 Git 写操作按相应授权执行；仅授权建议时交付处理建议。任务状态变更由任务维护流程承接。

## 完成检查与交付

按本轮管理问题核对实际结果：内容与依据一致，引用可以使用，材料的保留或处理符合实际依赖和访问需要。未决事项保留具体依据、影响及所需决定，明确本轮已完成的范围。

围绕本轮管理问题回复处理结论、实际改动和仍需承接的事项；涉及材料去留或 Git 时给出相应建议。现有材料已满足需要时，说明判断和依据即可完成本轮。
