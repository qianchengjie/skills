# 项目知识维护

维护后续理解、使用和维护项目所需的有效知识，使其准确、可找到、可追溯。探索、执行和验收材料提供整理依据，Spec、研究笔记和项目文档按实际用途承载知识。

## 确定本轮管理问题

根据用户目标、已有上下文和已确认方案确定本轮知识问题、涉及材料和操作范围。仅需判断时给出建议；已有授权覆盖的内容与引用维护直接完成。沿项目约定、目录和引用读取相关资料，识别已确认变化、内容过时或冲突、查找与引用问题，以及材料的实际依赖。涉及开发工作流 skills 的产物时，按需读取 [工作流材料职责](references/workflow-materials.md)。

以具体管理问题决定本轮动作和完成范围。知识库的长期组织方式尚未确定时，先沿用现有材料；只有当前问题确实依赖新的组织决定时，才将该决定交给调用方。现有内容准确、引用可用且满足使用需要时，维持现状即可。

## 判断内容与依据

区分已确认约定、观察或验证结果、候选方案和未决问题。以已确认需求和决定判断有效约定，以交付、验收、研究和排障证据判断已实现或已验证的范围；必要时定向读取代码、测试或契约。结论保留影响适用范围的条件与限制，摘要、索引和任务状态用于定位具体依据。

判断功能是否完成时，依据已有交付记录或用户对实际交付结果的确认；判断行为是否已被验证时，依据具体的验证结果及其覆盖范围。研究、排障和原型结论可以按已有证据独立保留，其验证结果与生产方案的采纳分别判断。

材料冲突时，查找明确的替代或裁决依据。仍无法确定的内容保留为具体未决项，继续处理不受影响的部分。新的需求取舍交给调用方，内容维护承接已经作出的决定。

## 按问题选择维护动作

| 实际需要 | 维护动作 |
| --- | --- |
| 已确认变化尚未反映，或现有内容有可核对的错误 | 更新相关材料的受影响部分，保留有效内容、适用条件与依据。 |
| 内容重复、入口难找、引用失效或相互矛盾 | 按材料职责厘清当前依据、摘要入口和历史证据的关系，修正引用；有裁决依据时协调相关表述。 |
| 已有明确的知识使用问题，现有材料尚不能回答 | 结合该问题的用途与依据，沿现有材料及引用核对实际缺口，再决定需要补充的内容。 |
| 工作材料中哪些内容值得沉淀或纳入 Git 存在疑问 | 确定所需知识和承载位置，指出必要的内容提炼与引用迁移；需要 Git 建议时列明提交候选。 |

对项目规定须由专门入口维护的内容，需要改动时将目标、具体变化和依据交给对应入口，按其协议写入和确认。领域、架构、规则和任务的专门维护职责见工作流材料职责；已有有效内容可以直接读取和引用。

补充内容的依据是已经明确的使用问题及其实际影响。现有材料及其引用能回答该问题时继续沿用；确有缺口时优先补充相关材料，需要新增载体时再按项目约定或本轮安排处理。承载方式确需另作决定时，返回具体选择及其影响，继续完成不依赖该决定的维护。

按材料用途选择写入内容：功能说明承载后续使用和维护所需的范围、行为、约束与理由；本次工作的执行状态、验收结果和验证覆盖用于本轮处理结论。研究笔记、历史决定和实验记录按其使用需要保留依据与原始事实，通过更正说明或替代引用关联后续变化。区分业务要求、外部契约与本项目的实现选择、配置和技术限制，使后续使用者能判断适用范围。

## 提炼长期知识与准备提交

长期知识承接材料中当前有效、后续仍需使用的含义。需要从工作材料中沉淀知识或准备提交时，按以下顺序逐份或分组判断：

1. **确定知识需要与表达**：识别后续仍需使用的业务概念、功能行为、规则与合同、关键决定及理由、研究结论和适用条件，说明缺失这些知识会影响什么。从讨论、实验和取舍中，将仍需承接的含义表达为当前约束、决定、行为、必要理由或有条件的研究结论，保持来源的确认状态、适用条件和约束强度。以缺少理由是否会妨碍理解当前关键决定或作出具体后续判断，决定是否承接该理由；当前约束或决定已能回答使用问题时，直接表达约束或决定。
2. **选择承载位置**：按项目已有职责和实际用途复用现有文档、代码、类型和测试，使当前知识直接可用，展开的决定依据和原始证据按需可查。代码已准确表达的实现事实继续引用代码；需要文字说明的意图、约束和理由放入对应文档。功能完成后，仍作为后续知识载体使用的 Spec 按已确认的最终范围整理；文件名或所在目录不决定其保留价值。
3. **按需判断提交范围**：需要 Git 建议时，结合知识承载关系、项目约定、当前跟踪与修改状态和协作访问需要，说明可直接提交、整理后提交、无需首次纳入的材料，以及已跟踪材料需要同步的更新。

完成任务的 Wayfinder 地图与决定票、to-tickets 拆分与实施票在必要知识与引用得到承接后，无需首次纳入 Git。执行记录、接口核对和验收报告作为判断依据，其独立记录价值按实际用途判断。

进行中的探索、实施和未决问题继续使用其工作材料；仍被下游实际消费的具体合同、实验数据和依据保持完整。研究笔记等本身能持续回答使用问题时，可以继续作为知识载体。

尚有必要知识未承接或引用未迁移时，列明具体缺口、承接位置和收尾动作。现有互引用于定位迁移工作，不作为将原文件纳入 Git 的独立理由。项目或调用方有明确的审计、复盘或原始记录访问要求时，沿用满足该用途的记录；已有可访问的 Git 或任务系统历史能满足所需追溯时，直接沿用。

提交候选只用于确定纳入 Git 的范围。材料的内容维护、归档、删除和 Git 写操作分别按本轮已有授权执行；任务状态变更由任务维护流程承接。

## 完成检查与交付

仅需判断时，以结论、依据和具体缺口清楚为完成标准；需要维护时，在已确定的维护范围内核对内容与依据一致，提炼后的确认状态、适用条件和约束强度保持原义，必要知识有合适载体，并检查本轮改动影响的入口与引用。需要提交建议时，说明候选范围及待整理事项。未决事项保留具体依据、影响及所需决定，明确本轮已完成的范围。

围绕本轮知识问题回复处理结论、实际改动和仍需承接的事项；需要提交建议时，先给出提交候选及理由，再说明必要的内容提炼与引用迁移。现有材料已满足需要时，说明判断和依据即可完成本轮。
