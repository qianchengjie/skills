# 项目知识库管理

在授权范围内管理项目知识及其承载材料，使有效内容准确、可找到、可追溯。长期沉淀以后续理解、使用和维护项目所需的有效知识为目标；探索、执行和验收材料可以提供整理依据，按其实际用途判断去留。

## 确定本轮管理问题

根据用户意图确定本轮主题、涉及材料、使用需要和操作范围。沿项目约定、目录和引用读取相关资料，识别已确认变化、内容过时或冲突、查找与引用问题，以及材料的实际依赖。涉及开发工作流 skills 的产物时，按需读取 [工作流材料职责](references/workflow-materials.md)。

以具体管理问题决定本轮动作和完成范围。知识库的长期组织方式尚未确定时，先沿用现有材料；只有当前问题确实依赖新的组织决定时，才将该决定交给调用方。现有内容准确、引用可用且满足使用需要时，维持现状即可。

## 判断内容与依据

区分已确认约定、观察或验证结果、候选方案和未决问题。以已确认需求和决定判断有效约定，以交付、验收、研究和排障证据判断已实现或已验证的范围；必要时定向读取代码、测试或契约。结论保留环境、时间、前提与限制，摘要、索引和任务状态用于定位具体依据。

涉及功能交付时，整体结论沿用已有整体验收依据或用户对实际已交付结果的明确确认；子任务证据按其覆盖范围使用。研究、排障和原型结论可以按已有证据独立保留，其验证结果与生产方案的采纳分别判断。

材料冲突时，查找明确的替代或裁决依据。仍无法确定的内容保留为具体未决项，继续处理不受影响的部分。新的需求取舍交给调用方，内容维护承接已经作出的决定。

## 按问题选择维护动作

| 实际需要 | 维护动作 |
| --- | --- |
| 已确认变化尚未反映，或现有内容有可核对的错误 | 在授权内更新相关材料的受影响部分，保留有效内容、适用条件与依据。 |
| 内容重复、入口难找、引用失效或相互矛盾 | 按材料职责厘清当前依据、摘要入口和历史证据的关系，修正引用；有裁决依据时协调相关表述。 |
| 已有明确的知识使用问题，现有材料尚不能回答 | 找到该问题的提出者、用途与依据，沿现有材料及引用核对实际缺口，再决定需要补充的内容。 |
| 材料是否继续保留或纳入 Git 存在疑问 | 先确定所需知识和承载位置，再判断最终保留集合与收尾动作，并在相应授权内落实。 |

普通材料的内容和引用更正按已有维护授权直接处理。对项目规定须由专门入口维护的内容，需要改动时将目标、具体变化和依据交给对应入口，按其协议写入和确认。领域、架构、规则和任务的专门维护职责见工作流材料职责；已有有效内容可以直接读取和引用。

补充内容的依据是已经明确的使用问题及其实际影响。现有材料及其引用能回答该问题时继续沿用；确有缺口时优先补充相关材料，需要新增载体时再按项目约定或本轮安排处理。承载方式确需另作决定时，返回具体选择及其影响，继续完成不依赖该决定的维护。

按材料职责组织内容：当前说明表达当前有效语义，按实际用途保留的历史决定和实验记录保持原始事实，通过更正说明或替代引用关联后续变化。区分业务要求、外部契约与本项目的实现选择、配置和技术限制，使后续使用者能判断适用范围。

## 处理材料去留

涉及收尾、保留或清理时，按以下顺序逐份或分组判断：

1. **确定知识需要**：识别后续仍需使用的业务概念、功能行为、规则与合同、关键决定及理由、研究结论和适用条件。说明缺失这些知识会影响什么；执行经过、任务状态和验收摘要用于判断本次工作，不进入长期知识正文。
2. **选择承载位置**：按项目已有职责承接有效知识，复用现有文档、代码、类型和测试。代码已准确表达的实现事实继续引用代码；需要文字说明的意图、约束和理由放入对应文档。Spec 按最终功能知识整理，文件名或所在目录不决定其保留价值。
3. **确定最终材料集合**：知识已有可靠承接、在用引用已迁移后，完成任务的 Wayfinder 地图与决定票、to-tickets 拆分与实施票默认退出正式知识入口，未跟踪的过程文件无需首次纳入 Git。执行记录、接口核对和验收报告作为本轮判断依据，其独立保留按明确的记录用途决定。

进行中的探索、实施和未决问题继续使用其工作材料；仍被下游实际消费的具体合同、实验数据和依据保持完整。研究笔记等本身能持续回答使用问题时，可以继续作为知识载体。

尚有必要知识未承接或引用未迁移时，暂时保留原材料，列明具体缺口和收尾动作，同时给出整理后的目标集合。现有互引用于定位迁移工作，不作为长期保留原文件的独立理由。项目或调用方有明确的审计、复盘或原始记录访问要求时，按该用途独立保留；已有可访问的 Git 或任务系统历史能满足所需追溯时，直接沿用。

需要 Git 建议时，结合最终承载关系、项目约定、当前跟踪与修改状态和协作访问需要，说明可直接提交、整理后提交、无需首次纳入或已跟踪材料的后续处理。最终提交集合与迁移前暂存材料分别说明。

迁移、归档、删除和 Git 写操作按相应授权执行；仅授权建议时交付处理建议。任务状态变更由任务维护流程承接。

## 完成检查与交付

按本轮管理问题核对实际结果：内容与依据一致，引用可以使用，材料的保留或处理符合实际依赖和访问需要。未决事项保留具体依据、影响及所需决定，明确本轮已完成的范围。

围绕本轮管理问题回复处理结论、实际改动和仍需承接的事项；涉及材料去留或 Git 时，先给出最终保留或提交集合及理由，再说明必要的内容提炼与引用迁移。现有材料已满足需要时，说明判断和依据即可完成本轮。
