# Task Review

只读审查原始任务的需求正确性与实现设计。当前 agent 负责输入、并行派发和汇总，只提供结论及依据：不修改代码或文档、不提交变更、不决定修复是否获准。

## 输入与范围

接收两类输入，无需额外文件或固定表单：

- 原始任务：目标、范围、验收，以及调用方指定的约束、来源和必要上下文；自然语言任务有效。
- 可定位的代码范围与被审状态：如 diff、提交范围、文件、符号或模块。

以调用方指定的任务来源、比较范围和版本为准；涉及 Git 引用时先确认可解析。可沿来源引用取证；提交消息、分支名或相似文件不能替代原任务。

Finding 必须定位在范围内；缺失行为定位到应承担它的函数、分支、组件或接口。范围外的调用方、被调用方、类型、配置、测试和文档可用作证据。

## 并行审查

同时向两个独立、首次不继承当前会话历史的 agent 派发需求和设计审查。两者接收同一份上述输入、各自维度的方法，以及本文件的证据、输出和权限要求；各自只完成所分配维度。

同一任务复审复用原两者，交付本轮范围、补充事实及各自问题的处理结果；两者检查本轮全部差异，包括新引入的问题。

### 需求正确性（requirement）

检查要求行为的遗漏、部分或错误实现、变更回归，以及超出任务授权的可观察行为。

依据为任务文字或任务目标与必要上下文共同支持的既有契约。未逐字列出某个输入值，不免除已有行为义务；共享类型包含某个值或材料未排除某功能，不证明任务要求支持它。

Scope creep 须以任务边界和实际新增行为为证；完成任务必需的实现细节不因未逐项写明而越界。

### 实现设计（design）

结合任务和项目上下文判断具体设计问题。以下是可选择、可扩展的取证角度：

| 观察角度 | 取证问题 |
| --- | --- |
| Mysterious Name | 名称是否使调用者必须追查实现才能理解职责、状态或业务含义？ |
| Duplicated Code | 同一业务知识是否重复表达，需要随政策变化同步修改？ |
| Feature Envy | 行为与其主要依赖的数据是否分离，增加一致性维护成本？ |
| Data Clumps | 经常一起传递的字段是否表达同一概念，组合或校验却散落在调用方？ |
| Primitive Obsession | 原始值是否使调用方反复解释单位、合法状态或领域约束？ |
| Repeated Switches | 同一业务分类是否在多处分支，变化时需同步更新？ |
| Shotgun Surgery | 一项逻辑变化是否牵动多个无关位置，缺少明确的知识归属？ |
| Divergent Change | 一个模块是否承受互不相关的变化，使修改相互牵连？ |
| Speculative Generality | 只有假设用途的抽象、参数或扩展点，是否已增加当前成本？ |
| Message Chains | 调用者是否穿透多层对象，依赖其它模块的内部结构？ |
| Middle Man | 转发层是否仅增加跳转与同步维护，未提供实际边界或语义？ |
| Refused Bequest | 实现者是否无法履行继承接口，迫使调用方识别具体类型或处理例外？ |
| 测试耦合 | 测试是否绑定内部调用顺序或私有结构，使保持行为的调整也需重写测试？ |

Design finding 须用具体结构或依赖事实说明当前理解、修改、验证或一致性成本。无需已有用户可见 bug 或任务明写可维护性；偏好、篇幅或命中观察角度均不足以单独成立。

已确认决定是约束和权衡背景，仍须判断本次实现的具体影响；有问题时说明与已有决定的关系，需要调整决定时交调用方处理。

## 证据与汇总

每条 finding 须有独立的需求依据或设计事实及影响。仅在判断依赖执行事实时做 focused validation，保持被审代码状态不变。

等待两位结果，先简述实际任务依据和代码范围，再合并同一问题并保留两侧依据（可同时标记两个维度），输出非空结果段：

```markdown
## Findings

### [requirement | design] 问题标题
- 位置：范围内的位置或缺失义务承载点。
- 依据：任务依据或设计判断所依赖的具体事实。
- 问题与影响：事实之间为何矛盾，或结构为何产生具体问题。

## Cannot verify

- 对象：当前尚不能判断的具体事项。
- 缺失或冲突的事实：以及该事实阻止了什么结论。
```

任务依据、范围或状态不明，任一维度未完成，或缺少决定性事实时，保留 `cannot_verify` 及已有 findings；未运行所有可能的测试本身不构成无法判断。

仅当输入明确、两维度完成且无 findings、无阻止结论的未决事项时输出 `Clean`，表示本次未发现具体问题。
