# whats-next：了解下一步有哪些选择

`whats-next` 是开发工作流中的导航 skill，帮助你根据当前意图了解下一步有哪些可用选择，以及这些选择分别适用于什么情况。它也可以介绍 Matt、Superpowers 和本仓库 skills 组合使用时的常见工作流。

具体执行要求见 [SKILL.md](../skills/whats-next/SKILL.md)。

## 根据你想做的事提供导航

它结合当前意图和已有会话上下文识别相关入口。入口明确时，直接推荐并简述理由；存在多个合理方向时，解释少量相关选择的适用条件。

例如，你说“这份需求太大了，想检查怎么拆、哪些先做”，可以直接推荐 [task-steward](task-steward.md)。如果只知道“需求已经写成 Spec”，则可以了解几个选择：需要生成分批交付的开发票并明确依赖时用 `to-tickets`，需要判断或落实需求拆分时用 `task-steward`，目标、范围与验收已明确，希望开始实现时用 [execute-task](execute-task.md)。

导航默认使用已有上下文；具体材料的评审和执行准备检查由相应 skill 承担。

## 了解常见工作流

你可以直接问“这套开发流程怎么走？”或“当天能做完的小修和几周的功能，分别从哪里开始？”

已有需求的目标、范围与验收明确且无需拆分时，可以直接进入执行。复杂需求可能需要先澄清问题、整理 Spec，再按需形成开发票；需要判断或落实拆分时，使用 `task-steward`。无需拆分时保留原需求，需要时形成平级 task 及其前置依赖。架构与规则维护也按当前需要加入。

开发、探索或日常维护中，需要更新知识内容、理清引用关系或判断材料去留时，可以推荐 [knowledge-steward](knowledge-steward.md)。例如，你说“研究结论更新了，决定地图还引用旧笔记，有些实验记录也不知道能不能清理”，就适合由它处理这些管理问题。任务或需求完成后也可以按需选择这一入口；现有材料满足需要时，继续后续工作或结束本轮。

各入口及其衔接条件见 [SKILL.md 的入口地图与常见 flow](../skills/whats-next/SKILL.md#入口地图)，整体分工见 [项目总览](overview.md)。

## 导航之后

`whats-next` 提供建议后结束，不修改项目材料，也不自动调用推荐的 skill。接下来由你或调用方安排具体工作，并遵循对应 skill 的执行约定。
