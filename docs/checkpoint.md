# checkpoint：把讨论接续到下一个会话

讨论还没结束，却需要换会话、工具或参与者时，`checkpoint` 把当前主题的目标、决定和未决问题保存为仓库中的 Markdown 文档，供后续恢复。

具体执行要求见 [SKILL.md](../skills/checkpoint/SKILL.md)。

## 保存下一次讨论需要的内容

新会话需要知道已经决定什么、还在考虑什么，以及哪些问题阻塞下一步。围绕单一主题维护这些内容，可以减少重新解释背景的成本。

同一主题持续更新同一份文档。新决定替代旧决定后，记录随之调整；已经解决的问题也从待讨论内容中移出。读者看到的是当前讨论状态。

首次保存可以指定仓库内的 Markdown 路径；未指定时，在 `docs/checkpoints/` 下选择位置。后续保存和恢复继续使用这份文件。

## 保留决定与事实的区别

只有你明确接受的决定才记为已确认。候选方案、AI 推断和未决问题分别标明，避免换会话后把推测当成既定要求。

例如，你同意尝试某种缓存方案，并不同时证明“现有缓存命中率很低”这个未经核验的判断。前者可以记录为决定，后者仍需保留其证据状态。

保存后的检查关注文档内部是否一致：结论有没有冲突、旧内容是否已被替代，以及同一决定是否重复表达。外部事实仍需要自己的验证依据。

## 恢复之后继续讨论

显式恢复时，AI 读取记录，简述当前状态，并从最先阻塞后续判断的问题继续。恢复本身只读；之后有新进展时，再显式保存。

正式 Spec、计划和任务仍由对应流程维护。Checkpoint 可以保留已进入正式材料的决定及其引用，帮助理解讨论来由；实际发现双方冲突时，把相关内容交给你裁决。

需要判断由哪个环节继续时，可以使用 [whats-next](whats-next.md)。整套流程见 [项目总览](overview.md)。
