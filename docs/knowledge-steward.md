# knowledge-steward：项目知识库维护

需求交付、问题排查、技术验证和重构都会留下有价值的信息。`knowledge-steward` 将这些知识整理到项目的正式文档中，供后续理解、维护和复用，并建议原材料的保留或清理方式。

具体执行要求见 [SKILL.md](../skills/knowledge-steward/SKILL.md)。

## 按知识主题维护

优先更新已有的普通功能说明、契约、操作文档或研究结论。项目规定须经专门维护入口或协议修改的文档只读取和引用；需要更新时，把具体改动及依据交给对应入口。每条完整约定保留一个正式维护位置，一项工作可以更新多处普通文档；只有确有独立维护用途时才新增文档。

知识保留适用范围、依据与限制。业务要求、外部契约和本项目的实现选择分别表达，便于另一个项目判断哪些要求需要沿用、哪些技术决定需要重新作出。

例如：

```text
使用 knowledge-steward 整理订单批量导出需求的交付材料。
需求由 specs/export-01.md、export-02.md、export-03.md 描述，
整体验收结论在对应任务中。更新现有功能说明，并建议原材料的保留方式。
```

也可以整理没有功能交付的技术工作：

```text
使用 knowledge-steward 整理支付回执去重窗口的验证结果。
把有依据的结论及适用条件补到现有接入文档中，
并建议研究笔记、决定票据和原型分支的保留方式。
```

## 理解 Matt 的文档分工

遇到 Matt skills 的产物时，先按项目的 `docs/agents/` 配置定位资料，识别词汇表、ADR、Spec、任务、Wayfinder 地图、研究笔记和原型的职责。具体说明见 [Matt 文档职责](../skills/knowledge-steward/references/matt-documents.md)。

地图提供查找决定的入口，具体答案仍要沿引用读取；研究结论保留证据和适用条件。已有正式记录充分承载知识时，可以继续沿用。

## 依据事实整理

功能约定沿用已确认需求和变更，实际交付范围依据整体验收结论或用户对实际已交付结果的明确确认。研究、排障和技术验证可以按已有证据独立沉淀。材料存在无法裁决的冲突时，先整理不受影响的部分，并返回具体未决问题。

文档整理本身不增加验收结论，也不改变需求或架构决定。

## 给出原材料建议

有效内容已经完整承接、在用引用已处理且历史仍可追溯的材料，可以退出活跃文档。仍承载独有约定、未决依据或后续任务依赖的材料继续保留，并说明原因。

是否保留与保存位置、是否纳入 Git 分别判断。需要选择保存载体时，结合项目约定、协作访问、追溯需要和已有载体的实际承接情况给出建议。

默认只维护正式知识文档，并给出原材料建议。来源材料的更正、归档、删除和任务状态变更由后续明确指令处理。

尚未结束的讨论可以使用 [checkpoint](checkpoint.md) 接续；整个开发流程见 [项目总览](overview.md)。
