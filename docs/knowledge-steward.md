# knowledge-steward：项目知识库管理

`knowledge-steward` 管理项目知识及其承载材料，使有效内容准确、可找到、可追溯。管理范围可以是一个主题、一批相关资料或已有知识库，按本轮需要处理内容更新、组织关系和材料去留。

Spec、任务、研究笔记、原型记录、项目文档及其引用都可以承载知识。即使长期组织方式尚未确定，也可以先维护现有材料。

具体执行要求见 [SKILL.md](../skills/knowledge-steward/SKILL.md)。

## 从具体管理问题出发

根据用户意图、现有材料和实际使用需要判断要处理什么，再选择维护动作：

| 当前情况 | 可能的处理 |
| --- | --- |
| 已确认的需求变化还未反映在 Spec 中 | 在授权内更新受影响内容，关联确认依据。 |
| 研究结论、原型验证与已采纳方案混在一起 | 理清确认状态和适用条件，保留各自证据与未决问题。 |
| 资料重复、引用失效或难以找到当前依据 | 维护现有目录、索引和引用，厘清材料之间的关系。 |
| 旧任务或实验材料是否保留存在疑问 | 检查独有内容、下游依赖和历史可访问性，给出处理结论。 |
| 现有知识与引用已经满足需要 | 说明依据，维持现状并结束本轮维护。 |

例如，可以在探索尚未结束时使用：

```text
使用 knowledge-steward 维护支付重试相关资料。
研究笔记已经更新，决定地图还引用旧结论，部分原型记录仍被后续任务使用。
请修正有依据的内容和引用，并判断哪些材料仍需保留。
```

补充内容先明确需要回答的具体使用问题及其依据，再沿现有材料和引用核对缺口。需要新增文档或索引时，位置按项目约定或本轮安排确定。本轮管理问题不依赖新的组织方案时，沿用现有材料即可完成维护。

## 保持各环节的职责

探索、研究、原型、需求准备、实现和审查会形成不同性质的知识与证据。`knowledge-steward` 管理这些内容及其材料关系；需要新调查、新决定、实现修复或重新审查时，交给相应环节。具体说明见 [工作流材料职责](../skills/knowledge-steward/references/workflow-materials.md)。

普通材料的内容与引用更正按已有授权处理。领域模型、架构、规则和任务等有专门维护约定时，变更遵循对应入口的协议。已有有效内容可以直接读取和引用。

例如，Wayfinder 地图维护索引，具体决定仍在票据或评论中；`checkpoint` 的快照保留讨论的确认状态，候选和推断仍按原状态使用；执行和审查交接提供其范围内的事实与发现。

## 保留依据与适用范围

功能约定沿用已确认需求和变更，整体交付结论依据整体验收或用户对实际已交付结果的明确确认，子任务证据按实际覆盖范围使用。研究、排障和原型结论可以独立保留，生产方案是否采纳另看相应决定。材料存在无法裁决的冲突时，继续处理不受影响的部分，并返回具体未决事项。

当前说明表达有效语义，历史决定和实验记录保留原始事实，通过更正或替代引用关联后续变化。业务要求、外部契约与本项目的实现选择分别表达，便于后续使用者判断适用范围。

## 按需要处理材料去留

涉及保留或清理时，仍承载独有内容、未决依据或后续依赖的材料继续保留。有效内容已有可靠承接、在用引用已处理且历史仍可追溯时，可以退出活跃材料；原始实验数据和验收条件等依赖需要完整承接。

需要 Git 建议时，再结合项目约定、跟踪与修改状态、协作访问及追溯需要，判断首次纳入、提交修改、维持现状或无需纳入。迁移、归档、删除和 Git 写操作按相应授权执行；仅授权建议时给出建议，任务状态由任务维护流程处理。

完成时说明本轮管理结论、实际改动和仍需承接的事项。是否需要新文件、材料处理或后续决定，都由本轮具体问题决定。

尚未结束的讨论可以使用 [checkpoint](checkpoint.md) 接续；整个开发流程见 [项目总览](overview.md)。
