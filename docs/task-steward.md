# task-steward：判断需求是否需要拆分

`task-steward` 是按需使用的拆分判断工具。它结合已有需求、任务划分和必要代码，判断当前范围是否需要拆分，或已有划分的粒度、依赖与需求覆盖是否合理。

具体执行要求见 [SKILL.md](../skills/task-steward/SKILL.md)。

## 什么时候使用

需求包含多组复杂工作、对任务边界存在争议，或已有划分因来源变化需要重新评估时，可以使用 `task-steward`。它给调用方提供判断依据；实施票由 `to-tickets` 生成和维护，目标、范围与验收已经明确的任务可以交给 [execute-task](execute-task.md)。

## 判断什么

以调用方指定范围为界，保持需求目标、约束、验收要求和已确认决定的原义。从实际实现关系出发，评估单项复杂度、核心设计耦合、成果承接与交接成本，推演候选边界和真实依赖。

成果可以是用户能力、内部模块、集成能力或技术验证证据。例如，具有稳定契约且能独立验证的内部模块，可以先交付，再由接入工作消费；需要共同确定核心状态或生命周期的工作，则可能适合放在一起。

除了逐项判断，还会核对整个范围的需求覆盖，确认连接工作、局部验收与真实组合验收有人承接，检查遗漏、重复与依赖环。来源变化时，只重评受影响部分，保留仍有效的结论。

## 得到什么

回复直接给出判断及决定性依据：

- **无需拆分**：说明完整范围为何能够可靠实施、验证和审查，或已有边界为何可以保持。
- **建议拆分**：说明候选成果边界、真实依赖、连接工作的归属和拆分收益；已有划分需要合并或调整时，给出对应建议。
- **暂无法判断**：说明缺少的信息、影响范围及需要补充的事实或决定，保留其他有依据的结论。

回复聚焦会改变下一步决策的关键依据、取舍与未决项。默认在回复中完成交付；你明确要求保存时，再写入指定位置。

判断完成后，由调用方决定是否调整任务、补充需求或进入后续执行。整套流程见 [项目总览](overview.md)。
