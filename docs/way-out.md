# way-out：重新判断当前方向

反复尝试没有进展、补丁越来越多，或几个现有方案都不合适时，可以使用 `way-out`。它先暂停当前路线，重新看真正目标，并比较一条结构上不同的可行方向。

具体执行要求见 [SKILL.md](../skills/way-out/SKILL.md)。

## 给当前方案一个可比较的替代方向

沿着同一路线投入越多，讨论越容易围绕“怎样让它成功”展开。暂时把这条路线放在一边，可以重新看到达到目标的其他方式。

例如，为了让用户及时看到统计结果，一直在压缩每次请求的计算时间；另一条方向可能是提前计算并展示更新时间。这会改变实现路径，也引入数据新鲜度的取舍，值得和原方案比较。

替代方向需要改变问题框架、路径、约束、责任或优先解决的未知之一。只是把原方案分阶段实施，仍然需要面对原来的关键假设。

## 比较之后，也可以继续原路线

当前方向有证据支持、障碍可以正常解决时，继续是合理结果。如果替代方案更合适，就调整方向；当前路线本身不值得继续时，可以放弃；关键事实不足时，先调查。

比较的目的，是让下一步更有依据。输出会收敛到一个判断，以及一个低成本、能尽快检验该判断的动作。上面的统计例子中，可以先确认用户能够接受的更新时间，再判断预计算是否值得继续探索。

## 与其他辅助 skill 的关系

[whats-next](whats-next.md) 判断当前问题该由谁继续，`way-out` 判断当前方向是否值得继续。方向确定后，再由相应环节承担需求讨论或具体实施。

跨会话保留这次讨论时可以使用 [checkpoint](checkpoint.md)，把已确认决定与待验证的想法分别保存。
